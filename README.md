# 🚀 Билим Арена

Мектеп үчүн интерактивдүү окуу платформасы: **доска — негизги экран, окуучулардын телефондору — пульт.**
Үч тил: кыргызча (негизги), орусча, англисче — аралашпайт. Каттоосуз иштейт; Supabase туташтырылса — аккаунттар жана жалпы маалымат.

Сайт: https://akbaralievernis.github.io/bilim_arena/

## Русский

### Как пользоваться
- **Учитель / доска** — `board.html`: выбрать предмет, тему и режим → QR-код или 4-значный код → ученики подключаются с телефонов → игра → разбор ошибок по навыкам.
- **Ученик** — `index.html` (главная), `games.html` (каталог: разделы «Языки», «Логика», «Командные», «Интерактивные», поиск, фильтры по предмету, типу, сложности, игрокам и устройству, сортировка; состояние в адресе, например `games.html?category=logic`), `play.html` (вход на урок), `practice.html` (практика), `speak.html` (произношение), `tasks.html` (домашние задания), `progress.html` (прогресс: уровень, XP, статистика, достижения, история игр, ошибки с объяснениями), `profile.html` (профиль: имя, картинка, язык, задания, вход на урок, режим учителя).
- **Учитель** — `teacher.html` (панель), `homework.html` (задания и аналитика класса, «Повторить тему» по реальным ошибкам), `questions.html` (библиотека и конструктор вопросов, 10 типов).

### Игры
Для доски — 9 игр из таблицы выше: быстрый опрос, захват территории, расследование, ошибка учителя, карта истории, кодовый замок, формула-бой, лаборатория, экономика города. Самостоятельно — «Говори!» (распознавание речи в браузере; где его нет — режим «Послушай и напиши»), старые языковые игры и «Мафия».

### Bilim Arena Race
Командная гонка по карте — отдельный сайт (https://bilimarenarace.vercel.app, своя база и вход учителя). Отсюда в неё ведут: страница `race.html` (ученик вводит код гонки, учитель создаёт гонку), карточка в каталоге («Командалык»), блок на главной, карточка в панели учителя и `play.html` — 6-значный код там сразу открывает гонку (код урока на доске — 4 символа). Ссылки строит `core/race.js` и передают язык сайта (`?lang=ky|ru`). Адрес гонки — `RACE_URL` в `core/config.js`.

### Связь доски и телефонов в строгих сетях (TURN)
Телефоны соединяются с доской напрямую (WebRTC). В некоторых школьных сетях (изоляция клиентов Wi-Fi, файрвол) прямое соединение невозможно — тогда нужен TURN-ретранслятор. Он включается в `core/config.js` → `TURN`:
1. Зарегистрируйтесь на [metered.ca](https://www.metered.ca/) (бесплатный тариф TURN).
2. Dashboard → TURN Server → скопируйте «Fetch Credentials» URL (`https://<имя>.metered.live/api/v1/turn/credentials?apiKey=…`).
3. Вставьте его в `TURN.credentialsUrl` и опубликуйте сайт.

Пустой `TURN` — работа как раньше (только STUN). Список серверов собирает `core/turn.js`: временные пароли кэшируются на час, сбой сервиса не мешает уроку. Тесты: `node --test tests/turn.test.mjs`. Проверка, что связь пройдёт и в строгой сети: откройте доску и телефон с `?relay=1` в адресе (например, `board.html?relay=1`) — тогда соединение идёт только через TURN.

Сейчас настроен Metered (бесплатно 500 МБ/мес): логин и пароль TURN записаны в `TURN.servers`. Расход виден в панели Metered → TURN Server & SFU.

### Свой сервер знакомства (signal/)
Доска и телефоны находят друг друга через сервер знакомства (по нему идут только служебные сообщения WebRTC, ответы учеников — напрямую). Раньше это был общий бесплатный сервер PeerJS; теперь можно поднять свой — папка `signal/`, Cloudflare Workers + Durable Objects (бесплатный тариф, без карты, не «засыпает»). Сайт сначала пробует свой сервер, при сбое сам переходит на общий.

Развернуть (один раз):
1. Создайте бесплатный аккаунт на [dash.cloudflare.com](https://dash.cloudflare.com/sign-up).
2. В папке `signal/`: `npm install`, затем `npx wrangler login` (откроется браузер — разрешите доступ) и `npm run deploy`.
3. Wrangler покажет адрес вида `bilimarena-signal.<аккаунт>.workers.dev` — впишите его в `core/config.js` → `SIGNAL.host` и добавьте `https://…` и `wss://…` в `connect-src` CSP всех страниц.

Сервер пускает только сайт из `ALLOWED_ORIGINS` (`signal/wrangler.toml`), ограничивает размер и частоту сообщений. Локально: `npm run signal:dev`, затем страницы с `?signal=local`; `?signal=public` / `?signal=own` — проверить конкретный сервер. Тесты протокола: в `signal/` — `npm test` (при запущенном `npm run dev`).

### Проверки
- `npm test` — модульные тесты (`tests/*.test.mjs`).
- `npm run test:e2e` — автотесты в браузере (Playwright, установленный Chrome): все страницы на трёх языках без ошибок и нарушений CSP, отдельные игры, урок с тремя телефонами через свой сервер знакомства, неверный код комнаты, вставка теста текстом. Сайт и сервер знакомства поднимаются сами.
- `npx playwright test --project=load` — нагрузка: `E2E_PHONES=50` телефонов, `E2E_STAGGER=15000` — вход в течение 15 с.
- `supabase/tests`: `npm test` — права доступа (RLS) на настоящем Postgres.

### Журнал ошибок
`core/errors.js` сообщает о сбоях JavaScript в таблицу Supabase `client_errors` (страница без параметров, текст ошибки, язык, браузер — без имён и id). Не больше 5 отчётов за загрузку страницы, на весь сайт — не больше 300 за 10 минут, хранятся 30 дней. Смотреть: Supabase → Table Editor → `client_errors`. На localhost выключен (включить: `?report=1`).

### Как добавить контент
- **Игра в каталоге:** запись в `data/games.js` (раздел, предметы, тип, сложность, игроки, устройства, иконка и тон иллюстрации).
- **Тема:** файл в `data/questions/` + запись в `TOPICS` (`core/curriculum.js`) с навыками.
- **Вопрос:** `{ id, skill, difficulty, type, prompt:{ky,ru,en}, …, explain:{ky,ru,en} }`. Типы: `choice`, `multiple`, `input` (`numeric`), `match`, `sort`, флаг `errorHunt` для «Ошибки учителя». Учитель может добавлять вопросы прямо в конструкторе.
- **Расследование / опыт / набор слов:** файлы в `data/investigations`, `data/labs`, `data/speaking`.
- Новые файлы добавить в список кеша `sw.js` и увеличить `VERSION`; при изменении страниц — поднять `?v=` у подключаемых файлов.
- **Перевод отдельной игры** (`games/*`, `web/*`): страница подключает `shared/lang.js` и свой словарь `i18n.js` вида `BALang.add({ 'Кыргызча сап': ['Русский', 'English'] })`. Ключ — кыргызская строка как в игре, `{n}` — подстановка. Текст страницы переводится автоматически; строки для canvas, `alert` и шаблонов берутся через `BALang.t('…', { n })`. Учебный материал, который нельзя переводить (слова для изучения), помечается `translate="no"`. Проверка: открыть игру с `?lang=en` — кириллицы на экране быть не должно, кроме учебного материала.
- **Мафия** — отдельное React-приложение: исходники в `mafia-src/`, переводы в `mafia-src/src/utils/i18n.js`, сборка `npm run build` (кладёт файлы в `games/mafia/`).

### Безопасность и данные
- Нет секретных ключей во frontend и в репозитории.
- Персональные данные минимальны: имя, роль, номер класса и аватар. Без облака всё хранится на устройстве (localStorage); с Supabase — ещё и в облаке, где правила RLS дают учителю доступ только к результатам, прогрессу и ошибкам своих учеников.
- Микрофон используется только на `speak.html` и только по нажатию; распознаёт сервис браузера, запись не сохраняется.
- На всех основных страницах стоит Content-Security-Policy: скрипты только с сайта и `cdn.jsdelivr.net`, соединения только с Supabase и сервером PeerJS, без встраивания в чужие фреймы. Новый внешний адрес нужно добавить в CSP всех 14 страниц.
- Библиотеки с CDN закреплены по точной версии; PeerJS и qrcode-generator загружаются с проверкой целостности (SRI) — подменённый файл браузер не выполнит. При обновлении версии пересчитайте хэш в `core/realtime.js`.
- Доска не доверяет телефонам (`core/realtime.js`): не больше 200 игроков, сообщения до 8000 символов и до 60 за 10 секунд (при флуде соединение закрывается), имена очищаются от управляющих символов. Каждый телефон получает секрет: вернуться на место ученика после обрыва может только он, а ответ засчитывается, только если пришёл по соединению этого ученика.

### Supabase: аккаунты и общие данные
Без настройки платформа работает локально, как раньше. После подключения:
- **учитель** входит по почте и паролю, создаёт классы — у каждого свой 6-значный код;
- **ученик** на странице ☁️ Аккаунт вводит код класса и имя — почта не нужна (анонимный вход Supabase);
- задания уходят ученикам класса, результаты — учителю; прогресс ученика и данные учителя хранятся в облаке, учитель видит всё с любого устройства;
- всё по-прежнему пишется сначала локально и работает без интернета, синхронизация — в фоне.

**Как подключить (один раз, ~10 минут):**
1. [supabase.com](https://supabase.com) → New project (регион поближе, например Frankfurt).
2. **SQL Editor** → вставить весь файл `supabase/schema.sql` → **Run**.
3. **Authentication → Sign In / Providers**: включить **Allow anonymous sign-ins** (вход учеников); Email оставить включённым.
4. **Authentication → URL Configuration**: Site URL — `https://akbaralievernis.github.io/bilim_arena/`, в Redirect URLs добавить `https://akbaralievernis.github.io/bilim_arena/account.html`.
5. **Authentication → Rate Limits**: поднять лимит анонимных входов (по умолчанию 30 в час с одного IP) — в школе весь класс выходит в интернет с одного адреса.
6. Встроенная почта Supabase отправляет лишь несколько писем в час: для многих учителей подключите свой SMTP (Authentication → Emails) или отключите подтверждение почты.
7. **Project Settings → API**: скопировать **Project URL** и ключ **anon public** в `core/config.js`.

⚠️ В `core/config.js` — только `anon`-ключ. Ключ `service_role` в код не вставлять никогда.

**Проверка схемы и синхронизации:** `cd supabase/tests && npm install && npm test` — схема и `core/cloud.js` прогоняются на настоящем Postgres (PGlite): 37 проверок правил доступа и 23 сквозных сценария учитель ↔ ученик.

### Ограничения и что дальше
- **Без Supabase** данные хранятся на каждом устройстве отдельно; домашние задания передаются через урок на доске (`core/sync.js`).
- **Ученик привязан к устройству**: анонимный аккаунт нельзя открыть на другом телефоне. Если ученик сменит устройство — он снова входит по коду класса (учитель может удалить старую запись в списке класса).
- **AI** (генерация заданий, объяснения) — только через сервер (например, Supabase Edge Function), чтобы ключ API не попал в браузер.
- Без своего сервера знакомства (`signal/`) комнаты работают через общий сервер PeerJS; при его недоступности урок на телефонах не подключится (самостоятельные режимы работают).
